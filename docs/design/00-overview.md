# NCC 语言设计文档

## 核心理念

> **语法基线 = C++26。只允许从 C++26 中删除语法，不允许新增语法。**

唯三语法例外（用户明确批准，其余章节严格遵守"只删不加"）：

1. **`comp`** —— 加在函数/类/结构体前面，声明"这是编译期计算"，统一取代
   `constexpr` / `consteval` 一整套关键字，并驱动反射与代码生成。保留裸
   `comp { ... }` 块，用于顶层批量操作。`comp` 函数可以接受 `type T` 形式
   的类型参数（C++26 标准模板参数是 `typename T`，这里简化为 `type`），并
   通过 `<>` 语法调用——**`template` 关键字被彻底删除**，所有泛型机制统一
   为 `comp` 函数 + 反射生成。`const` 保留其运行时不可变语义，和 C++ 完全
   一致。
2. **枚举携带数据**（tagged variant，如 `RGB(u8,u8,u8)`）——C++26 的
   `enum class` 不能携带数据，这里作为受限扩展单独说明。
3. **`import` 关键字**（C++20 已有，但扩展用于包导入）—— 用于从 `package.toml`
   导入外部依赖包，统一模块和包管理。

除以上三点外，本文档中出现的一切语法都必须是 C++26 标准里已经存在的语法
（可能是被限制/裁剪过的子集），不存在第四种"新语法"。

### 三类例外的语法边界

- **`comp` 声明与块**：允许 `comp` 修饰函数、类型和编译期常量，允许
  `comp { ... }` 块、`type` 类型参数/返回类型，以及声明中的泛型参数列表。
  泛型函数写作 `comp T max<type T>(T a, T b)`，泛型类写作
  `comp class CustomPtr<type T>`。返回类型和普通参数声明沿用 C++ 写法，
  不引入 `fn` 关键字或 `参数名: 类型` 语法。求值与实例化阶段在 comp 章节定义。
- **Tagged enum**：允许枚举变体携带载荷及泛型枚举声明。每个变体具有可命名的
  载荷类型（如 `Shape::Circle`），支持按载荷声明顺序进行标准结构化绑定；
  无载荷变体对应空类型。载荷值可构造相应的枚举值。
  不引入模式匹配表达式、模式分支箭头或通配符语法。

Tagged enum 的特殊成员函数由编译器生成，赋值采用先构造临时值、成功后交换
的实际实现；构造失败时原变体保持不变。其拷贝、移动、析构和异常保证遵循载荷
类型与 C++ 特殊成员函数规则。
- **扩展 `import`**：将包清单中的依赖纳入模块导入解析；名字归属与冲突处理
  支持 `import module as alias;` 模块别名以解决同名导出；`as` 属于本项唯一扩展，
  不引入 namespace 或新的通用命名机制。

`match(value, handler...)` 是普通调用形式的 **`comp` 函数**，通过公开的
comp/反射能力检查处理函数并生成分发代码，没有专用的词法、语法或编译器特权。
运行时枚举的处理发生在生成代码中；这与编译期检查的具体阶段划分将在 comp
章节统一定稿。循环使用 `for`/`while`，报错使用标准 `throw`。
编译期求值期间未捕获的异常使编译失败并产生诊断；运行时仍遵循异常传播规则。
显式不可恢复的终止使用普通终止函数调用，不引入宏式报错语法。

**"只删不加"贯彻到底，体现在以下方向：**

- **头文件、`namespace`、`std` 前缀全部删除**，只保留 C++20 已有的模块
  （`export module` / `import`）作为唯一的代码组织机制；核心库（字符串、
  容器、反射函数等）作为语言内置的全局符号，不需要任何限定名或 `import`
  就能直接使用。
- **名称查找以模块替代 namespace**：删除 `namespace` 后 ADL 失去载体，改由
  **关联模块**承担同一职责——未限定名的候选集是「当前作用域 + 已导入模块的导出
  符号 + 每个实参类型定义所在模块的导出符号」。非成员运算符与泛型中的依赖调用
  依此解析；候选同等匹配时报歧义，用 `mod::name` 消解。核心库符号不享有优先级。
  详见 [名称查找](01-modules.md#名称查找)。
- **智能指针直接沿用标准 C++ API**：`unique_ptr<T>` / `shared_ptr<T>` /
  `weak_ptr<T>`，以及核心库提供的 `make_unique` / `make_shared` 工厂函数，
  一个符号都不改名、不发明。指针类型和工厂都是 `comp` 函数：`<>` 消耗类型参数
  生成类型或类型专用的工厂函数，`()` 里的构造参数按 C++ 规则转发，所有权、
  拷贝、移动和异常语义与标准一致。
  直接构造函数 + `new` 仍然有效。默认赋值语义完全是
  标准 C++ 的特殊成员函数规则：资源封装类型负责定义或删除所有权操作，
  组合类型优先遵循 **Rule of Zero**。编译器不推断裸指针或整数句柄的所有权。
  从具名左值转移资源通常使用 `move()`；右值、返回局部对象和拷贝消除遵循
  C++ 原有规则，`move()` 本身不保证实际发生移动。不引入"默认 move"、
  `Copyable` 接口、引用借用检查这类自造机制——`T&`/`T*` 就是标准 C++ 的
  引用/指针，没有任何额外检查，能力边界与原生 C++ 完全一致。
- **对象构造统一使用聚合初始化和构造函数**（聚合初始化是 C++20 已有语法，
  构造函数是 C++ 原生语法）。用户自定义类型可以选择只用聚合初始化（不写
  构造函数），也可以定义构造函数用于资源获取和初始化逻辑。核心库类型
  （`unique_ptr`、`String`、`File` 等）与用户类型使用相同的机制，没有特殊
  例外。
- **统一反射句柄**：`Info` 同时表示编译期反射值和运行时类型描述符。`comp`
  在编译期生成运行时描述符、字段访问器和方法桥接函数；运行时通过
  `dynamic_type_of` 获取 `Info`，查询类型、字段和方法，并通过统一的
  `get_field`/`set_field`/`invoke` 访问。运行时 `Info` 不能用于 `splice` 或生成新类型。
- **GPU 设备视图**：拥有 GPU 内存的 `Vector<T, Device::Gpu>` 保持值语义；
  `DeviceView<T>` 是不拥有数据的轻量视图，GPU lambda 按值捕获视图而不复制数据。
  异步操作完成前视图的所有者必须保持有效，完成句柄通过 `wait()` 明确同步。
- **结构化并发**：所有任务属于 `TaskScope`，作用域结束前必须完成、取消或显式
  `detach()` 转移；`parallel`、`TaskScope::spawn` 和 `Channel` 都遵循同一生命周期规则。
  创建执行单元只有 `TaskScope::spawn` 一个入口，不提供 `Thread::spawn`；需要真正的
  OS 线程时显式经由 `import pthread` 调用 C API，明确脱离调度器。
- **通道所有权**：`Channel<T>::create()` 返回 `Sender<T>` / `Receiver<T>` 一对，
  `Sender` 可 `clone()`；最后一个 `Sender` 析构时通道自动关闭，不依赖人工协调
  关闭时机。`recv()` 返回 `Optional<T>`，通道关闭且排空后为空值。
- **异步句柄不可静默丢弃**：`Completion` / `Completion<T>` 标注 `[[nodiscard]]`，
  析构时阻塞等待操作完成——丢弃返回值退化为同步执行，语义正确但失去并行收益。
  `Task<T>` 不同：它有 `TaskScope` 兜底，析构等同 `detach()`，作用域结束时仍会等待。
- **GPU 捕获边界**：GPU kernel 只接受设备可传输值；标量、按值捕获的 `DeviceView<T>`
  和由它们组成的聚合类型可传输，裸指针、引用、`this`、CPU 容器和未知地址空间
  类型默认拒绝。该检查只约束 GPU 调用边界，不是通用借用检查。
- **GPU 索引统一**：后端使用 `block_id * block_dim + thread_id` 和向上取整的
  grid 大小，所有全局访问执行边界检查；零长度输入不启动 kernel。
- **GPU 构建与运行分离**：编译目标由 `--target` 指定，不要求构建机有 GPU；
  无设备时由开发者选择 CPU 回退或在执行 GPU 操作时抛出 `GpuUnavailable`。
- **可重现构建输入显式化**：普通 `comp` 不访问外部环境；文件、环境、网络、
  工具和生成输出只能由受限 `build.ncc` 声明并纳入构建图与缓存键。
- **目标范围**：NCC 仅支持 64 位目标；32 位目标不在语言、ABI 和核心库支持范围内。
- **类型转换只保留一个函数 `cast<T>(value)`**，值、指针和引用目标分别返回
  对应的 `Optional`，多态转换只做定义明确的运行时检查，不复制或转移借用对象。
  删除 `static_cast`/`dynamic_cast`/`reinterpret_cast`/`const_cast`，统一到
  `cast<T>`。`is<T>(value)` 是不复制、不移动对象的检查简写，等价于
  `cast<T>(value).has_value()`。位模式重解释不另立函数，而是通过目标类型
  `cast<Bits<T>>(value)` 表达——语义始终由目标类型决定，转换入口只有一个。
- **`concept` 关键字删除**：类型约束用 `comp bool` 函数表达。`requires` 语法
  保留（C++20 已有），因为它解决的是约束的**应用位置**（模板参数、函数签名），
  而 `comp bool` 函数解决的是约束的**定义**，两者职责不重叠。
- **`template` 关键字删除**：所有泛型定义改用 `comp` 类型生成函数或泛型声明，通过
  `<>` 语法调用时触发编译期代码生成。例如 `Vector<int32_t>` 等价于编译期调用
  `Vector(^^int32_t)`，其中 `Vector` 是一个返回类型的 `comp` 函数。
- **`co_await` 与 awaiter 协议删除**：保留 `co_yield` / `co_return` 用于惰性
  序列，删除 `co_await`、`await_ready` / `await_suspend` / `await_resume`、
  `await_transform` 以及用户可见的 `initial_suspend` / `final_suspend`。
  异步并发由绿色线程（`TaskScope`）承担，协程只承担惰性序列；语言层面无法用
  协程搭建第二套异步机制。详见 [并发](08-concurrency.md#三惰性序列生成器协程)。
- **预处理器整体删除**：`#include`、`#define`、`#ifdef`、`#pragma`、`#` 与 `##`
  全部移除。各项能力由既有机制承担：模块替代 `#include`，`comp` 常量与 `comp`
  函数替代宏，`comp` 块内的 `if` 配合 `profile()` / `target_os()` 替代条件编译，
  反射替代字符串化与拼接。`assert` 是核心库的普通运行时函数（源码位置由
  `SourceLocation::current()` 默认实参在调用处取得），不是宏。
- **`static_assert` 关键字删除**：编译期断言改用核心库的 `comp` 函数
  `comp_assert(cond, message)` 与 `compile_error(format, ...)`。理由是消息可以
  用统一的格式化引擎拼入类型名等信息（`static_assert` 只接受字符串字面量），
  且条件的求值规则与 `comp` 一致，不必单独规定何谓常量表达式。
- **attribute `[[...]]` 保留**，包含实现定义的 `[[ncc::...]]`。判据：**attribute
  必须可忽略**——删除程序中所有 attribute 后，程序必须仍然合法且语义等价（允许
  性能与诊断变差）。`[[...]]` 的语法形式是 C++11 起的既有产物，标准要求实现忽略
  未知 attribute，因此实现定义的 attribute 位于标准预留的位置，不构成第四种语法
  例外。通不过该判据的构造是语言扩展，必须按语法例外重新审批，不得以 attribute
  形式引入。非标准 attribute 一律加 `ncc::` 前缀以便与 C++26 既有 attribute 区分。

## 设计原则

1. **零成本抽象** - 不为不用的功能付出代价
2. **只删不加** - 语法基线是 C++26，新增语法仅限 `comp`、tagged enum 和扩展 `import`
3. **一个问题一个解法** - 智能指针用标准三个、转换只有一个函数、反射只有一套 API
4. **编译期优先** - 能在编译期做的就不要拖到运行时
5. **不做超出标准 C++ 语义之外的隐藏检查** - `T&`/`T*` 就是标准引用/指针，
   能力边界与原生 C++ 完全一致，不新增一套"看起来安全但不完备"的编译器检查
6. **标准拷贝与移动语义** - 拷贝、移动和特殊成员函数生成完全遵循 C++。
   编译器不推断裸资源的所有权；资源封装类型负责定义所有权操作，组合类型
   优先遵循 Rule of Zero。具名左值通常显式使用 `move()`，保留 C++ 对右值、
   返回局部对象及拷贝消除的既有规则。
7. **核心库与用户代码一致** - 核心库类型使用与用户代码相同的语法、
   `define_class` 和 `StorageOps` 机制；优化依据公开类型属性，不按名称授予特权。
