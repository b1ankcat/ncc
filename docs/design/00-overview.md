# NCC 语言设计文档

## 核心理念

> **语法基线 = C++26。只允许从 C++26 中删除语法，不允许新增语法。**

唯三语法例外（用户明确批准，其余章节严格遵守"只删不加"）：

1. **`comp`** —— 加在函数/类/结构体前面，声明"这是编译期计算"，统一取代
   `constexpr` / `consteval` 一整套关键字，并驱动反射与代码生成。保留裸
   `comp { ... }` 块，用于顶层批量操作。`comp` 函数可以接受 `type T` 形式
   的类型参数（C++26 标准模板参数是 `typename T`，这里简化为 `type`），并
   通过 `<>` 语法调用——**`template` 关键字被彻底删除**，所有泛型机制统一
   为 `comp` 函数 + 反射生成。`const` 保留其运行时不可变语义，和 C++ 完全
   一致。
2. **枚举携带数据**（tagged variant，如 `RGB(u8,u8,u8)`）——C++26 的
   `enum class` 不能像 Rust 那样携带数据，这里作为受限扩展单独说明。
3. **`import` 关键字**（C++20 已有，但扩展用于包导入）—— 用于从 `package.toml`
   导入外部依赖包，统一模块和包管理。

除以上三点外，本文档中出现的一切语法都必须是 C++26 标准里已经存在的语法
（可能是被限制/裁剪过的子集），不存在第四种"新语法"。

**"只删不加"贯彻到底，体现在以下方向：**

- **头文件、`namespace`、`std` 前缀全部删除**，只保留 C++20 已有的模块
  （`export module` / `import`）作为唯一的代码组织机制；核心库（字符串、
  容器、反射函数等）作为语言内置的全局符号，不需要任何限定名或 `import`
  就能直接使用。
- **智能指针直接沿用标准 C++ API**：`unique_ptr<T>` / `shared_ptr<T>` /
  `weak_ptr<T>`，一个符号都不改名、不发明。唯一删除的是 `make_unique` /
  `make_shared` 这套工厂函数，直接用构造函数 + `new`。默认赋值语义完全是
  标准 C++ 的 **Rule of Zero**：类型能拷贝就默认拷贝，管理独占资源的类型
  会自动隐式禁用拷贝，需要转移时显式调用 `move()`。不引入"默认 move"、
  `Copyable` 接口、引用借用检查这类自造机制——`T&`/`T*` 就是标准 C++ 的
  引用/指针，没有任何额外检查，能力边界与原生 C++ 完全一致。
- **对象构造统一使用聚合初始化和构造函数**（聚合初始化是 C++20 已有语法，
  构造函数是 C++ 原生语法）。用户自定义类型可以选择只用聚合初始化（不写
  构造函数），也可以定义构造函数用于资源获取和初始化逻辑。核心库类型
  （`unique_ptr`、`String`、`File` 等）与用户类型使用相同的机制，没有特殊
  例外。
- **反射不区分"静态/动态"两套 API**：对静态已知类型，反射查询本身是
  `comp`（consteval），编译期展开成普通代码，同一份函数编译期/运行时通用。
  "通过基类指针拿到的多态对象、运行时才知道具体派生类"这个真正动态的场景，
  不单独开一套结构，只是往同一套反射 API 里加一个桥接函数。
- **类型转换只保留一个函数 `cast<T>(value)`**，检查即"转换后看有没有值"。
  删除 `static_cast`/`dynamic_cast`/`reinterpret_cast`/`const_cast`，统一
  到 `cast<T>`。`is<T>(value)` 作为语义简写，等价于 `cast<T>(value).has_value()`。
- **`concept` 关键字删除**：类型约束用 `comp bool` 函数表达。`requires` 语法
  保留（C++20 已有），因为它解决的是约束的**应用位置**（模板参数、函数签名），
  而 `comp bool` 函数解决的是约束的**定义**，两者职责不重叠。
- **`template` 关键字删除**：所有泛型定义改用 `comp type` 或 `comp fn`，通过
  `<>` 语法调用时触发编译期代码生成。例如 `Vector<int32_t>` 等价于编译期调用
  `Vector(^^int32_t)`，其中 `Vector` 是一个返回类型的 `comp` 函数。

## 设计原则

1. **零成本抽象** - 不为不用的功能付出代价
2. **只删不加** - 语法基线是 C++26，新增语法仅限 `comp`、tagged enum 和扩展 `import`
3. **一个问题一个解法** - 智能指针用标准三个、转换只有一个函数、反射只有一套 API
4. **编译期优先** - 能在编译期做的就不要拖到运行时
5. **不做超出标准 C++ 语义之外的隐藏检查** - `T&`/`T*` 就是标准引用/指针，
   能力边界与原生 C++ 完全一致，不新增一套"看起来安全但不完备"的编译器检查
6. **默认拷贝，move 显式化** - 完全遵循标准 C++ 的 Rule of Zero：类型能拷贝
   就默认拷贝，管理独占资源的类型自动隐式禁用拷贝，需要转移时用 `move()`
7. **核心库与用户代码一致** - 核心库类型使用与用户代码相同的语法和机制，
   没有"魔法"特权
